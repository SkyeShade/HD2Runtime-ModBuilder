# HD2Runtime ModBuilder 1.1.0

Adds support for **HD2Runtime SDK 0.26.0**. The new authoring controls come from the capability files that 0.26.0 publishes; nothing is inferred from names. ModBuilder ships with the verified 0.26.0 SDK metadata, so it works offline from the first start.

**Download:** `HD2Runtime-ModBuilder-v1.1.0-win-x64.zip` (Windows 10/11 x64). Extract it and run **`HD2RuntimeModBuilder.exe`**, or use **Install update** from 1.0.0 or 1.0.1. Mods built with these features need HD2Runtime 0.26.0 or later.

## New with SDK 0.26.0

### All magazine variants
- Every resolved magazine option of a weapon appears in a compact variant switcher, with its default badge, semantic ID and the weapons it fits. The Liberator shows its Extended (default), Short and Drum magazines and an option known only from its unlock list.
- Each option is edited on its own: capacity, starting, supply and spare magazines, **reload duration** and **ergonomics modifier**.
- Editing a magazine definition never changes which magazine is equipped; selection and presets stay read-only. Options Runtime cannot resolve (the LAS-5 heatsinks) are listed without controls.

### Third-person reticle
- An On/Off switch on 70 player weapons and, inside their Support stratagem pages, 14 support weapons.
- The APW-1 Anti-Materiel Rifle change is gameplay-proven and needs no acknowledgement. The others need "I understand this effect is not gameplay-confirmed".
- Weapons whose reticle Runtime cannot map show the reason and no control.

### Fire modes
- The weapon's native four-slot fire-mode list: slot 1 is the default, and the others are cycled in game. Add, remove or reorder modes where Runtime publishes the list; for example, JAR-5 can gain Automatic.
- Beam, charge, wind-up and special fire-control weapons show Runtime's blocker instead of controls.

### Vehicle mounted weapons
- Under Stratagems → Support → Vehicles, each mount is its own weapon section with **Weapon** (fire rate, ammo, reload, mount health/armor), **Projectile**, **Damage** and **Explosion** groups.
- Exosuit left and right arms, tank cannons and coaxial machine guns stay separate. Each group says whether its values are mount-local, shared with other mounts, or a shared definition with other users. Shared groups ask "I understand this affects other users of this object" once, next to the group.

### Mission uses
- "(o) Unlimited ( ) Limited: [ N ]" for stratagems whose use count Runtime publishes. Only the transitions Runtime allows are offered, and Unlimited is written as Runtime's own `'unlimited'` token.
- Making an Exosuit unlimited is gameplay-proven; other changes need the unverified-effect acknowledgement. Eagles keep their uses-per-rearm setting and have no mission-use control.

### Backpack-fed support weapon ammo
- The M-1000 Maxigun, B/FLAM-80 Cremator and GL-28 Belt-Fed Grenade Launcher fire from their backpack. Their Support page now has a **Backpack ammo** section: capacity, starting ammo and ammo from supply, written to the backpack through the support weapon.

### Drop pod contents
- A **Drop pod** section for call-ins with an authorable hellpod rack: the spawn count and slots 1–4. Each slot can be emptied or hold a pickup from Runtime's catalog, grouped as Support Weapons, Backpacks, Ammo, Stims, Grenades and Supplies, with **Proven**, **Rack-compatible**, **Unverified**, **World pickup** and **Package risk** badges.
- A replacement asks "I understand this replacement may not load correctly"; a spawn-count change asks for the unverified-effect acknowledgement.
- Shared racks explain who else uses them. **Surplus EAT Allocation** shows Granted stratagem → Drop pod → Spawn count → Slots and warns that it also changes the normal EAT-17.
- Slots 5–8 and read-only racks have no controls.

### Mod Options
- New numeric values can become in-game options within their published ranges: magazine values, vehicle weapon values, drop-pod spawn counts and finite mission-use counts.
- Pickups, fire-mode lists, Unlimited uses and the reticle cannot, because Runtime binds option values only to numbers.

### Review and build
- Every new edit appears on Changes (mounted weapons under their vehicle, drop pods as their own entry), can be reset per field or per object, and is shown exactly in Lua Preview and Build / Export with the acknowledgements Runtime requires.

## Compatibility
- Projects bound to an older SDK open unchanged, keep their feature set and show none of the 0.26.0 controls until you rebind them.
- Rebinding a 0.25.x project to 0.26.0 keeps every edit and produces the same Lua. Only a new 0.26.0 edit raises the project file to format 8.
- Updating works from 1.0.0 and 1.0.1. Your projects, exports, SDK cache, imported game icons and settings stay in `%LOCALAPPDATA%\HD2RuntimeGUI\`.

## Known limits (HD2Runtime 0.26.0)
- Fire modes stay read-only for beam, charge, wind-up and special fire-control weapons. Some reticles are read-only.
- Magazine selection and presets are not writable, and the three LAS-5 heatsink options are unresolved.
- Drop-pod slots 5–8 are never authored; 8 racks are read-only.
- Some vehicle mounts hold no weapon component (FRV racks, the Maelstrom coaxial mount, the Breakthrough left arm).
- The Cremator's own weapon fields stay blocked; only its backpack ammo is writable.
