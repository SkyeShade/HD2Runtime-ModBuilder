# HD2Runtime ModBuilder 1.4.3

A small polish of the **presentation trait editor**. It adds no new HD2Runtime capability: since 1.4.0 this editor has written HD2Runtime's existing `hd2.fields.presentation.traits` field, and 1.4.3 makes its purpose and the trait IDs explicit.

**Download:** `HD2Runtime-ModBuilder-v1.4.3-win-x64.zip` (Windows 10/11 x64). Extract it and run **`HD2RuntimeModBuilder.exe`**, or use **Install update** from any earlier version.

**New projects require [HD2Runtime 0.28.1](https://github.com/SkyeShade/HD2Runtime/releases/tag/v0.28.1)**, the same as 1.4.2. Projects bound to an older SDK keep requiring that SDK's Runtime until you rebind them.

## Presentation traits
- In a weapon's **Armory labels** section, the trait list is now titled **Presentation traits (up to 5)** (it was "Displayed traits"). It states what it edits: HD2Runtime's `hd2.fields.presentation.traits`, the trait IDs the armory shows, in this order. The wiki traits are not changed.
- Each trait shows its label together with its exact published ID (for example TEAM WEAPON · `team_weapon`); the generated Lua writes the IDs. Adding, removing and reordering traits, the five-trait limit and the separate labels for the two INCENDIARY traits work as before.
- Where HD2Runtime publishes a weapon's traits only as blocked (CQC-20 Breaching Hammer, EAT-411 Leveller, EAT-700 Expendable Napalm), the editor now shows **Unavailable** with HD2Runtime's reason instead of nothing.
- On the Changes page, a saved trait edit shows the trait labels instead of raw IDs.
- For example, changing the GR-8 Recoilless Rifle from TEAM WEAPON · ANTI-TANK to EXPENDABLE writes one guarded operation: `expect={'team_weapon','anti_tank'}`, `value={'expendable'}`, with `allow_unverified_effect=true` as HD2Runtime requires for this field.

## Unchanged
- The operations ModBuilder generates, the project format, the bundled HD2Runtime 0.28.1 SDK and project SDK bindings are unchanged, and so are the guards and shared-value checks.
- 1.4.2's distinction between the game's own trait labels and the wiki's trait list stays as it was, as do the Changes-page performance improvements.
