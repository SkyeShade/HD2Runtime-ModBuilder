# HD2Runtime ModBuilder 1.3.1

A small fix for **projectile swaps on weapons that already have projectile stat edits**. The swap is now handled where you make it, instead of blocking the build and sending you to Changes.

**Download:** `HD2Runtime-ModBuilder-v1.3.1-win-x64.zip` (Windows 10/11 x64). Extract it and run **`HD2RuntimeModBuilder.exe`**, or use **Install update** from any earlier version.

## Changes
- **Swap with edits, decided in place.** When you pick another projectile (or **Reset projectile**) while the current one has edits (projectile, damage or explosion values, or a replaced impact/expiry explosion), a small prompt appears under the selector. It lists your changed values and offers **Switch and keep my values**, **Switch and discard them** or **Cancel**. Nothing is saved until you choose.
- **Keeping values** applies the same values to the new projectile in the same save, measured against its own base values. A short note afterwards says what happened, for example "Kept 2 values on the new projectile." Values that already match the new projectile's base are not written. Values the new projectile does not have are listed instead of failing the swap.
- **Reset projectile on Changes** asks the same question in its row: **Reset and keep my values** / **Reset and discard them** / **Cancel**.
- **Projects with leftover edits.** A project saved by an earlier ModBuilder can have edits on a projectile the weapon no longer fires. That weapon's Projectile section now opens by itself with a **Needs attention** badge and **Keep on current projectile** / **Discard them** buttons. The build banner says **Open *weapon*** and takes you there, not to Changes.
- Editing a leftover value on the projectile the weapon fires now simply replaces the old edit. Before, this showed "Composition target changed. Reset the old object edit before editing the new object."

## Unchanged
- Generated Lua, the project format and HD2Runtime behaviour are unchanged. Kept values are written exactly like values you set by hand on the new projectile.
- Shared-object writes still carry `allow_shared` and show their warning. No acknowledgement is needed.
