# HD2Runtime ModBuilder 1.2.0

Adds support for **HD2Runtime SDK 0.27.0 — automatic asset loading**. Reference swaps (drop-pod contents, projectiles, explosions and vehicle mounts) no longer need anyone to carry the donor item: HD2Runtime loads the package holding the replacement's assets before it writes the swap. ModBuilder now shows that clearly, and keeps it separate from whether a swap is gameplay-compatible.

**Download:** `HD2Runtime-ModBuilder-v1.2.0-win-x64.zip` (Windows 10/11 x64). Extract it and run **`HD2RuntimeModBuilder.exe`**, or use **Install update** from any earlier version. ModBuilder ships with the verified 0.27.0 SDK metadata, so it works offline from the first start.

## Important fix: "SDK unavailable" after HD2Runtime 0.27.0 was released
Earlier ModBuilder versions checked every new HD2Runtime release they found. Once 0.27.0 was published, that check failed on its new metadata and ModBuilder showed **"SDK unavailable"**. 1.2.0 fixes this properly:
- Each ModBuilder release now declares the **newest HD2Runtime SDK it supports** (1.2.0: 0.27.0, shown in Settings as *Supported up to*). A newer SDK release is reported ("needs a newer HD2Runtime ModBuilder") and is never downloaded or offered, so a future HD2Runtime release cannot break this version.
- A release whose metadata this version cannot read is skipped; your installed SDK and projects stay available.

## Automatic asset loading
Every reference-swap editor shows one compact asset state:
- **Assets live-verified**: HD2Runtime loads the package automatically, and it was loaded in a passing live test (EAT-700 and Grenade Box pod payloads, the LAS-58 Talon projectile).
- **Assets loaded automatically**: the dependency is known; HD2Runtime loads it before the write.
- **Assets always loaded**: the pickup is in a package the game always has loaded.
- **Assets unknown** (warning): HD2Runtime cannot name the package; the replacement may appear as a missing asset unless the item is already in the mission.

An expandable **Asset dependency** section (collapsed by default) shows the package name, whether it was live-tested, how far the loader is proven for that kind of reference, and HD2Runtime's reason when a dependency is unknown. It also explains what happens in game: the write waits for the assets (`waiting_for_assets`, at most 90 s); if they cannot be loaded, HD2Runtime rejects it with `ASSET_UNAVAILABLE` and the original reference stays in place.

### Drop-pod contents
- Payload choices show their asset state next to Proven / Rack-compatible / Unverified and World pickup, and the dropdown marks each option (for example "Rack-compatible · assets live-verified").
- The old **Package risk** warning is gone wherever HD2Runtime now loads the package itself. Pickups with an unknown package keep an explicit warning.
- The two rack/pickup combinations that passed live tests (Stalwart pod → EAT-700, MG-43 pod → Grenade Box) show **Live-verified pair**.

### Projectiles and explosions
- Sources from another weapon's package are offered when HD2Runtime knows that package. **LAS-58 Talon** is now a valid projectile source (live-verified with the SMG-32 Reprimand), and no warning says the donor weapon must be equipped.
- Explosion swaps show the source weapon's asset state; that loader is proven offline. HD2Runtime's projectile compatibility classes are unchanged.

### Vehicle mounts
- Mount swaps show the replacement weapon's asset state (loader proven offline). The inconclusive FRV → Bastion live test is shown as "not yet live-tested", not as a failure.

## Assets loaded ≠ gameplay-proven
Loading assets answers only "will the replacement appear?". Drop-pod replacements and vehicle mount swaps keep a separate **Gameplay compatibility unverified** warning and are still written with `allow_unverified_reference`, exactly as HD2Runtime requires, including the live-verified pairs.

## Generated mods
Mods use the same typed HD2Runtime APIs as before. No `hd2.require_assets` or package calls are generated: HD2Runtime infers and loads dependencies itself. Mods using these swaps need HD2Runtime 0.27.0 or later to get automatic loading.

## Existing projects
- Projects stay pinned to their SDK and open unchanged.
- Rebinding a 0.26.0 project to 0.27.0 keeps every edit and produces the same Lua. Changes whose only difference is that HD2Runtime now loads the assets automatically (reworded pod and mount package warnings, projectile sources that are now auto-loaded) are carried over without new review flags.
- Your projects, exports, SDK cache, imported game icons and settings stay in `%LOCALAPPDATA%\HD2RuntimeGUI\`.

## Known limits (HD2Runtime 0.27.0)
- 71 of 331 reference-swappable objects have no known package (59 of 79 mounted weapons, Ammo Box (pod), Health Pack (pod) and a few others). They show **Assets unknown**.
- Vehicle-mount and explosion-reference loading is proven offline only; mount swaps remain gameplay-unverified.
- Multiplayer: asset loading is local to the player running the mod.
- HD2Runtime 0.27.0 also publishes a new throwables authoring domain (`hd2.throwable`); ModBuilder does not author throwables yet.
