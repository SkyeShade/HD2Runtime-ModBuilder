# HD2Runtime ModBuilder application updates

This covers updates of the ModBuilder application itself. HD2Runtime SDK updates are separate; see "HD2Runtime SDK cache and updates" in the README.

## Release contract

The only update source is GitHub Releases of `SkyeShade/HD2Runtime-ModBuilder`, over HTTPS, without a token.

| | |
| --- | --- |
| Discovery | `GET https://api.github.com/repos/SkyeShade/HD2Runtime-ModBuilder/releases?per_page=20`, User-Agent `HD2Runtime-ModBuilder/<version>` |
| Release | Tag `v<x.y.z>` (stable semantic version). Drafts, prereleases and prerelease versions are ignored. `html_url` must be `https://github.com/SkyeShade/HD2Runtime-ModBuilder/releases/tag/v<x.y.z>`. |
| Package asset | `HD2Runtime-ModBuilder-v<x.y.z>-win-x64.zip` (at most 512 MB) |
| Manifest asset | `modbuilder-update.json` (at most 64 KB) |
| Checksum asset | `HD2Runtime-ModBuilder-v<x.y.z>-win-x64.zip.sha256` (for people; the app uses the manifest) |
| Download URLs | Exactly `https://github.com/SkyeShade/HD2Runtime-ModBuilder/releases/download/v<x.y.z>/<asset>`. Redirects may only go to `github.com`, `release-assets.githubusercontent.com` or `objects.githubusercontent.com` over HTTPS. |

A release without both the package and the manifest is not offered. The newest qualifying release is compared with the running version; if it is not newer, nothing is shown.

### `modbuilder-update.json`

Generated by `scripts/publish-windows.ps1`:

```json
{
  "format": 1,
  "product": "HD2Runtime ModBuilder",
  "version": "1.0.0",
  "tag": "v1.0.0",
  "asset": "HD2Runtime-ModBuilder-v1.0.0-win-x64.zip",
  "size": 97870321,
  "sha256": "<64 lowercase hex>",
  "entrypoint": "HD2RuntimeGUI.exe",
  "updater": "HD2RuntimeModBuilder.Updater.exe",
  "commit": "<40 lowercase hex>"
}
```

Unknown properties are rejected. `version`, `tag`, `asset` and `size` must match the release, `entrypoint` and `updater` must be exactly those names (the manifest cannot point at other files), and when GitHub publishes an asset `digest` it must equal `sha256:<sha256>`.

### Package layout

The ZIP is the flat application folder: `HD2RuntimeGUI.exe`, `HD2RuntimeModBuilder.Updater.exe` and everything else at the root, plus `modbuilder-files.json`:

```json
{ "format": 1, "product": "HD2Runtime ModBuilder", "version": "1.0.0",
  "files": [ { "path": "HD2RuntimeGUI.exe", "size": 123, "sha256": "<hex>" }, … ] }
```

The inventory lists every other file with its size and SHA-256. The installed copy of it tells the next updater which files belong to the app.

## Flow

1. **Check.** Once after startup, in the background. A result from the last hour is reused. Offline, rate-limited, malformed or failed checks are silent (the status appears in Settings → Application updates). Settings has **Check for updates**, which always queries GitHub.
2. **Banner.** A newer version shows a banner under the titlebar with **Install update**, **View release notes** (the official release page, opened in the browser) and **Dismiss**. Dismissing hides that version (persisted in `%LOCALAPPDATA%\HD2RuntimeGUI\app-update.json`); a newer release shows the banner again.
3. **Install** (in the app, `AppUpdateService`):
   - Only a release installation (one with `modbuilder-files.json`) updates itself. A development build, or a folder the user cannot write to, gets **Open release page** instead.
   - Download `modbuilder-update.json` and validate it.
   - Download the ZIP to `%TEMP%\HD2Runtime-ModBuilder-Update\<version>\` with the exact size.
   - Verify the size and SHA-256 against the manifest.
   - Extract to `…\staged\`. Rooted, `..`, drive-qualified, duplicate, link and reserved (`.modbuilder-update-backup`) entries are rejected. The ZIP must contain exactly the inventory's files, each with its recorded size and SHA-256, and include `HD2RuntimeGUI.exe` and the updater.
   - Start `staged\HD2RuntimeModBuilder.Updater.exe --pid --started --install --staged --version --result`, then quit.
   - Any failure before this point keeps the app running, removes the temporary files and shows the error in the banner.
4. **Replace** (the updater, running from the staged copy, so nothing in the installation folder is locked by it):
   - Wait for the app's process to exit. The process ID is checked together with its start time.
   - Re-check the staged inventory and files.
   - Move the installed app's files (the old inventory's files, plus any path the new package writes) into `<install>\.modbuilder-update-backup\`.
   - Copy the new files in, then the new inventory.
   - Retry locked files briefly.
   - On any failure: delete what was copied, move the backup back and restart the old version.
   - On success: delete the backup and stale directories, and start the new `HD2RuntimeGUI.exe`.
   - Files in the folder that are not part of the app are never touched.
5. **Next start.** The updater writes `%LOCALAPPDATA%\HD2RuntimeGUI\app-update-result.json`. The app shows the result once (for example "HD2Runtime ModBuilder was updated to 1.1.0." or the failure reason), deletes the file, and after a success removes the staging folder and any leftover backup.

The updater is a separate self-contained, trimmed, single-file executable (about 11 MB) with no dependency on the MAUI app or an installed .NET. It is the new release's own updater, verified as part of the package, and it runs outside the installation folder. No administrator rights are requested. User data in `%LOCALAPPDATA%\HD2RuntimeGUI\` (projects, exports, SDK cache, imported icons, preferences) is outside the application folder and is never part of an update.

## Publishing a release

1. Set `Hd2RuntimeGuiVersion` in `Directory.Build.props`, add `docs/release-notes/v<x.y.z>.md`, and commit.
2. Run `./scripts/publish-windows.ps1` on the clean tree. It fails on uncommitted changes, wrong metadata, a non-reticle icon, unexpected files, or a manifest that does not match the ZIP.
3. Create the GitHub release with tag `v<x.y.z>` on `SkyeShade/HD2Runtime-ModBuilder` (not a draft or prerelease). Use the release notes as the description and upload the three files from `artifacts/release/`: the ZIP, `modbuilder-update.json` and the `.sha256`.
4. Do not replace assets of a published release. Publish a new version instead; the app caches the release it found for up to an hour.
